# 工作台开发：分工

和 Hermes 改造同一个模式。代码仓库：https://github.com/zzyxiangnian-star/hermes-workbench ；你电脑上的本地文件夹建议 `F:\工作台开发\hermes-workbench`。

| 谁 | 负责 |
|---|---|
| Claude（总指挥） | 方案、接口和数据结构约定、写任务卡、审查交回的报告和代码。不写代码 |
| 你电脑上的 Antigravity（Gemini） | 全部开发，按 W 开头的任务卡做；每张卡做完推到仓库，写报告 |
| 你 | 把任务卡全文发给 Antigravity；把报告转回给我；确认方案和界面 |

## 两条硬要求（用户定）
1. **风格贴合 Hermes**：所有界面照 Hermes 桌面版原生风格（hermes-agent 的 apps/desktop/DESIGN.md、styles.css），只用 Hermes 的 CSS 变量和 SDK 组件，不写死颜色、不引入别的组件库和字体。每张卡交回时附一张和 Hermes 原生界面（如侧栏会话列表、设置页）并排的对比截图，并用 `/impeccable critique` 对照 DESIGN.md 自查一遍。
2. **参考 GitHub 优质项目**：每张卡写明这次要参考的开源项目（方案文档“GitHub 可参考项目”一节是总表）。动手前先看参考项目怎么做，报告里写清借鉴了什么。许可证规矩：MIT、Apache 的代码可以拷，拷了在仓库 `THIRD_PARTY.md` 记来源项目、文件和许可证；GPL、AGPL、无许可证、非商用的只看设计，不拷代码（要交付给客户，算对外分发）。

## 规矩
- 第一版所有工作台打成**一个插件**（“工作台”），各部门工作台是插件里的模块；以后要分开下发再拆。
- 提交信息以卡号开头（如 `W01:`），每张卡在仓库 `docs/reports/` 里留一份报告。
- 不把任何 Key、令牌、客户数据写进仓库；演示数据全部用假数据。
- 可以用 impeccable 技能审查打磨（`/impeccable critique`、`/impeccable polish`），不要运行 `/impeccable init` 或 `document`。

## 流程
1. Claude 写任务卡，放在这个文件夹
2. 你把任务卡全文发给 Antigravity
3. Antigravity 推到仓库并写报告
4. 你告诉我做完了，我审查后出下一张卡
