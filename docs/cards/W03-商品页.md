## 背景
商品页要代替运营每天人工检查：后端（Cursor 做的 C01）已经能导入报表、按 4 条规则找出异常。接口说明在 `docs/CONTRACT-products.md`，**以它为准**。
后端地址默认 `http://127.0.0.1:8000`。本地开发时先在另一个终端启动后端：
```
cd server
python -m pip install -e ".[dev]"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 页面要求
**页头操作区**（W01 留的 `data-slot="actions"`）：右边主按钮“导入报表”，旁边次要按钮“规则”。

**顶部一行汇总**：必须处理 N、提醒 N、涉及商品 N，用小号文字和 Badge，不做大卡片。

**筛选行**：SegmentedControl（全部 / 有问题 / 必须处理 / 提醒）、店铺下拉、SearchField（标题、编码、货号）。筛选条件改变时回到第 1 页。

**商品列表**（平铺行，不用卡片墙）：标题（截断，悬停 Tip 全名）、店铺（平台小图标 + 店名）、价格 / 底价（低于底价时价格用 `--ui-error` 颜色）、库存、活动、问题徽标（必须处理用 destructive，提醒用 warn）。底部分页：“共 N 件，第 x / y 页”+ 上一页、下一页。

**点一行 → IssueDrawer**（右侧滑入）：商品基本信息；该商品的问题列表（规则名、原文 message、发现时间、状态）；每条问题可以“标为已处理”“忽略”并写备注（PATCH /issues/{id}），操作后列表和汇总、左栏徽标同步刷新。

**ImportDialog**：选店铺（没有店铺时可在这里新建：平台 + 店名 + 品牌）、选文件（xlsx/csv）、上传；完成后显示“成功 N 行，失败 M 行”，失败行列出行号和原因；“查看商品”关闭弹窗并刷新列表。

**RulesDrawer**：4 条规则，每条一行：名称、级别、开关（Switch）、参数输入（价差 %、最低库存、指定活动名）；改完点“保存”PATCH，再点“立即检查”调 `POST /api/rules/run`，显示新增、已处理的条数。

**状态**：加载中用 Loader 或 Skeleton；出错用 ErrorState（显示后端返回的中文 message 和“重试”）；**连不上后端**时显示专门的空状态：“没有连上工作台服务”，说明当前地址，给“重试”和“更改地址”（改 settings.ts 里的地址）。

## 视觉规范
沿用 W01：只用 Hermes 的 CSS 变量和 SDK 组件，不写死颜色。这次 SDK 可以多用 `SegmentedControl, SearchField, Switch, Loader, Skeleton, ConfirmDialog`（先查 `apps/desktop/src/sdk/index.ts` 确认导出名，预览里的 stub 同步加）。抽屉和弹窗的样式照 Hermes 原生（看 `apps/desktop/src/components/ui/` 里的 dialog/sheet 实现和 DESIGN.md 的“浮层”一节），能直接用 SDK 导出的就用 SDK 的。
